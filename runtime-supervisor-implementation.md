# Nova runtime reliability implementation

Implemented on 22 October 2026. Executable: `build-runtime-supervisor/Nova.exe`.

## Root causes addressed

- `main.cpp` performed one acquisition/routing cycle and returned after Branch 3. It now initializes once, calls `processOneRequest`, and uses a supervisor menu between requests.
- Branch 3 owned its goal, decomposition, history, validation budget, and progress as locals. A resumable in-memory session now retains those across dependency failures and user continuation.
- Planner transport errors had no machine-readable category. Curl timeout and HTTP status classification now flow through `LLMResponse`, `NextActionDecision`, and typed whole-task outcomes. The 10-second connection and 60-second request deadlines are unchanged.
- Runtime browser observation depended on English words in generated descriptions. Browser primitives now activate observation through structured execution state.
- Previous DOM dumps accumulated in history, and progress comparison depended on a mismatched display marker and regenerated IDs. Browser wire data is separate from concise messages. Planner history is bounded to ten entries of at most 768 bytes; the current observation has bounded text, fields, and at most 24 prioritized controls. Semantic fingerprints exclude observation IDs, while current planner observations retain IDs.
- File readback could succeed and then be followed by a failing final planner call. Explicit per-step artifact postconditions now track verified completion; all verified artifact steps finish before another planner request.
- Directory collisions lacked evidence distinguishing an existing directory from a conflicting file. Existing destinations remain primitive failures, but now carry `already_exists`, the policy-checked path, and directory evidence. Only a matching declarative directory goal may accept this as satisfied.

## Runtime behavior and bounds

`R` retries from the preserved session; `C` resumes the same goal with fresh browser observation; `V` abandons the session and starts normal input acquisition; `Q` exits. EOF on the menu also exits. Menu selection does not launch the speech pipeline. A valid decomposition is reused on continuation. Invalid decomposition may be retried.

A planner timeout, connection failure, rate limit, or provider failure gets at most one automatic retry for the same observed state. Authentication failures are not automatically retried. Remaining failures pause with a typed cause and retained progress. Browser recovery permits at most two recoverable failures per bounded execution pass, refreshing observation and replanning rather than blindly repeating a stale action. Repeated stale IDs are rejected. Two consecutive semantic no-change transitions pause for intervention. Each pass has twelve iterations; explicit user continuation grants another bounded pass without discarding progress.

A readiness timeout followed by meaningful observed change allows replanning from the current DOM. Unchanged readiness failures cannot be accepted as completion. Last execution issue, recovery, current blocker, and verified progress are reported separately. Browser navigation and typed input become reported progress only after observation confirms the corresponding facts.

Automatic filesystem completion requires explicit artifact metadata describing the entire logical step. Untyped legacy steps retain observed planner verification. Discovery operations do not mark an artifact step complete. Directory and populated-file targets must match the declared name and parent-location clues. New-file goals cannot bypass an existing-file collision with `text.write`; legitimate existing-file write steps retain that primitive. No website, product, language, filename, or algorithm branches were introduced. The filesystem location resolver and path policy were not edited.

Raw browser data can optionally be written to a diagnostic file using `NOVA_BROWSER_DEBUG_LOG`. It is excluded from normal reports and prior planner history. Sessions persist in memory for the running process; restart/disk checkpoint recovery is outside this milestone. Readback proves the requested generated bytes were written; it does not prove an arbitrary generated program is correct.
